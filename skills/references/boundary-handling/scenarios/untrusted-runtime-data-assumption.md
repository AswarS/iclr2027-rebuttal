## Problem Description

当代码从语言运行时的内省 API（如模块注册表、导入系统、插件发现机制）获取文件路径或资源标识符，并将其直接传递给操作系统级别的路径操作（解析、规范化、stat 调用、符号链接遍历）时，隐含地假设这些路径是合法且可被 OS 接受的。然而，运行时注册表只是外部环境数据的传导管道，其中可能包含对宿主操作系统非法的字节序列（如 POSIX 系统上的嵌入空字节）、畸形编码、或指向不可达文件系统位置的路径。这种隐式信任假设在标准开发环境中不会暴露，但在网络文件系统、容器化部署、动态模块加载器或异构挂载点等环境下会导致间歇性崩溃。

## Root Cause Analysis

问题的根本原因是**信任边界的错误放置**。开发者的心智模型将"来自自身运行时内部 API 的数据"等同于"经过验证的合法数据"，但实际的信任边界位于应用程序与操作系统的接口处，而非运行时 API 的返回点。

运行时的模块注册表聚合了来自多种异质来源的路径：文件系统发现、zip 导入、命名空间包、C 扩展、网络挂载卷等。这些来源中的任何一个都可能注入在特定宿主 OS 上非法的路径数据。这种损坏是非确定性的、系统特定的，且完全超出应用程序的控制范围。因此，在数据源头进行清洗是不可靠的——唯一可靠的策略是在**消费点**进行防御性处理。

## Solution Strategy

### 识别信号
- 观测到的现象:
  - 在非标准部署环境（网络文件系统、容器、异构挂载点）中出现间歇性 `ValueError`（如 "embedded null byte"）、`OSError` 或其他 OS 级别的路径拒绝异常
  - 崩溃发生在遍历模块路径、解析资源标识符等迭代操作中，导致整个操作中止
  - 问题在标准开发环境中无法复现，属于环境依赖型回归
  - 异常堆栈指向路径规范化函数（如 `os.path.realpath`、`pathlib.resolve`）或 stat 系统调用

### 解决步骤
1. **审计所有消费点**：定位代码中每一处将运行时内省 API（模块注册表、`sys.modules`、`__path__`、插件系统等）返回的路径字符串传递给文件系统操作的位置。
2. **扩展异常处理覆盖范围**：在这些消费点的 try/except 块中，除了已有的文件系统异常（`FileNotFoundError`、`PermissionError`）外，增加对数据完整性异常（`ValueError`——嵌入空字节、畸形编码）及其他 OS 级拒绝异常的捕获。遵循同一代码块中已有的异常处理风格和模式。
3. **添加 debug 级别日志**：在 except 分支中记录 debug 级别的日志，包含出错的路径值和异常信息，确保诊断可见性而不干扰正常运行。
4. **跳过并继续**：对出错的条目执行 skip-and-continue 策略，而非中止整个迭代操作，保证其余合法路径的处理不受影响。
5. **验证一致性**：确认修改后的异常处理与相邻代码的错误处理模式保持一致，避免引入风格不统一或遗漏。

### Why This Works
在消费点（而非数据源头）进行防御性处理是正确的，因为路径数据的损坏具有非确定性和系统特异性，应用程序无法控制生产者。通过在 OS 接口边界处捕获异常，我们将信任边界放置在了正确的位置。skip-and-continue 策略确保单个异常条目不会导致整个操作的级联失败，而 debug 级别日志在不产生运行时噪音的前提下为环境特定问题的调查者保留了诊断线索。这种方法承认了一个关键事实：运行时 API 的输出本质上是未经清洗的外部数据，必须以处理不可信输入的方式来对待。

## Boundary Cases
- **嵌入空字节的路径**：某些动态模块加载器或损坏的 `.pyc` 文件可能在 `sys.modules` 中注册包含 `\x00` 的路径，POSIX 系统的 `realpath` 会抛出 `ValueError` 而非 `OSError`。
- **网络文件系统上的瞬态不可达路径**：NFS/CIFS 挂载点可能在迭代过程中变为不可达，产生非标准的 `OSError` 子类。
- **命名空间包的 `None` 路径**：命名空间包的 `__file__` 可能为 `None`，需要在路径解析前进行空值检查，否则会在类型层面失败而非文件系统层面。
- **Zip 导入和虚拟路径**：`zipimport` 产生的路径在文件系统上不存在实际对应物，传递给 `os.path.realpath` 可能产生意外结果。
- **Windows 上的长路径和保留名称**：超过 260 字符的路径或使用 Windows 保留设备名（CON、NUL 等）的模块路径可能触发 OS 级拒绝。
- **混合编码环境**：在 locale 设置不一致的系统上，`sys.path` 中可能存在无法用当前文件系统编码解码的 `bytes` 路径，导致 `UnicodeDecodeError`。

## PR Examples
- django__django-11583：Django 的自动重载器在遍历 `sys.modules` 中的模块路径并调用 `pathlib.Path.resolve()` 时，未处理包含嵌入空字节的路径导致的 `ValueError`，在特定部署环境下引发间歇性崩溃。修复方式为在路径解析的 try/except 中扩展捕获 `ValueError`，跳过异常条目并继续迭代。
