## Problem Description

递归函数在遍历和转换复合/嵌套数据结构时，仅显式处理了一种容器类型（通常是字典/映射），而对其他容器类型（列表、元组等）采取了直接返回的策略，导致嵌套在未处理容器类型内部的值完全绕过了转换逻辑。这种模式在数据清洗、敏感信息脱敏、配置规范化等场景中尤为危险——函数在简单测试用例中表现正常，但在真实世界的异构嵌套结构中会静默地产生不完整的结果或泄露敏感数据。

## Root Cause Analysis

问题的根本原因是**容器类型同质性假设（Container Type Homogeneity Assumption）**。开发者在编写递归遍历逻辑时，倾向于将数据结构心智模型简化为单一容器类型的嵌套（例如"字典套字典"），而忽略了真实世界的配置和数据结构中频繁出现的异构容器组合——字典的值可能是列表，列表的元素可能是字典，元组中可能嵌套着包含敏感键的映射。

每一个未被递归处理的容器类型都成为转换逻辑的**隐形逃逸通道**：数据流经该节点时不会触发任何转换，而调用者对此完全无感知。这属于典型的**不完整抽象（Incomplete Abstraction）**问题——抽象层声称提供了"递归转换"的能力，但实际上只覆盖了数据树中的部分节点类型。

## Solution Strategy

### 识别信号
- 观测到的现象:
  - **静默数据丢失/泄露（Silent Data Loss）**：嵌套在列表或元组内部的敏感值未被脱敏/转换，而同等深度但位于字典内部的值被正确处理
  - **部分结果（Partial Result）**：递归转换函数的输出在简单结构上正确，但在包含异构容器的复杂结构上产生不完整的转换结果
  - **测试覆盖盲区**：单元测试仅使用纯字典嵌套结构，未覆盖列表/元组等混合容器场景

### 解决步骤
1. **枚举所有可能出现的容器类型**：审查被遍历数据结构的完整类型空间。对于配置/设置类数据，至少需要覆盖字典（dict）、列表（list）和元组（tuple）。检查实际数据样本或类型定义以确认。
2. **为每种容器类型添加显式递归分支**：在递归函数中，对每种已识别的容器类型添加独立的处理分支，迭代其元素并递归调用自身。使用 `isinstance(value, dict)` 处理映射，`isinstance(value, (list, tuple))` 处理序列。
3. **序列元素递归时传递中性键值**：序列容器的元素没有命名键，递归时应传入一个不会触发基于键名匹配的中性/空键值（如空字符串 `""`），确保元素本身不会被错误地整体替换，但其内部嵌套的映射仍能正确触发键级别的检查。
4. **避免使用泛型可迭代检测**：优先使用显式类型检查（`isinstance`）而非通用的可迭代判断（如 `hasattr(v, '__iter__')`），防止字符串、字节串等可迭代但非容器的类型被意外分解。
5. **保持原始容器类型不变**：递归处理后返回与输入相同的容器类型——如果输入是元组，返回元组而非列表，避免下游代码因类型变化而出错。

### Why This Works

递归转换的正确性要求数据树中的**每一个节点类型**都被显式处理。通过为所有已知容器类型添加递归分支，消除了隐形逃逸通道，确保转换逻辑能够到达数据树的每一个叶子节点，无论其祖先路径上经过了哪些容器类型的组合。显式类型检查在保证完整覆盖的同时，避免了对字符串等"伪容器"的误处理，在安全性和精确性之间取得了正确的平衡。

## Boundary Cases
- **字符串和字节串**：它们在 Python 中是可迭代的，但不应被当作容器递归分解，否则会导致逐字符处理和无限递归。必须使用显式类型检查而非泛型可迭代检测。
- **自定义容器类型**：如 `OrderedDict`、`defaultdict`、`namedtuple` 或第三方库的容器类型，需要根据实际使用场景决定是否纳入递归处理范围。`isinstance(value, dict)` 通常能覆盖 `OrderedDict` 等字典子类。
- **深度嵌套的混合结构**：如 `{"key": [{"secret": "password"}, ({"token": "abc"},)]}` 这样的多层异构嵌套，要求每一层的容器类型都被正确处理。
- **空容器**：空列表 `[]`、空元组 `()`、空字典 `{}` 应被安全地原样返回，不触发异常。
- **循环引用**：虽然在配置数据中罕见，但如果数据结构可能包含循环引用，递归函数需要额外的访问标记机制以防止无限递归。
- **序列中的非容器标量值**：列表或元组中的字符串、数字等标量值应直接返回，不应尝试递归。

## PR Examples
- **django__django-12700**：Django 的请求数据清洗/脱敏函数在递归处理配置结构时，仅处理了字典类型的嵌套，导致嵌套在列表或元组内部的敏感配置值未被脱敏，造成静默的信息泄露。修复方案为在递归函数中添加对列表和元组的显式递归分支，并在处理序列元素时传递中性键值以避免误触发键名匹配。
